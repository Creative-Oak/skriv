# Plan: Phase 0 + Spike 1 (ODF-first word processor)

## Context

We're building an open-source, ODF-first word processor. It is the first piece of an M365 replacement for people who live in Word, including Danish public-sector staff moving to LibreOffice. The research report (`~/Desktop/word_processor.pdf`, read in full) recommends:

- our own ODF-shaped model as the source of truth;
- LibreOffice as the test oracle;
- retiring the ODT round-trip risk first.

This session scaffolds the repo, writes the ADRs and spike briefs, and runs **Spike 1**: can our own Rust ODT reader/writer round-trip real ODT files without losing anything? We measure that with a LibreOffice-oracle harness. Earlier word-processor work (the birk branch `claude/word-processor-prototype-*`) is ignored, as instructed.

**Decisions made with the user**

- The word processor gets its **own repo**. It must be embeddable into birk, which is AGPL-3.0.
- The licence is **MPL-2.0**. MPL §3.3 allows combination with (A)GPL code, so birk can depend on it. The reverse would not work, which is why the core takes no AGPL dependencies.
- The working name is **`skriv`**, at `~/Development/skriv`. Renaming costs little: it only touches crate and package names.
- Embedding path: the Rust core is later built to WASM and published as `@skriv/*` npm packages. birk's pnpm workspace consumes them through a git or file dependency. The TypeScript tooling matches birk: pnpm 10, Node ≥22, TypeScript 7, Biome 2.6, Vitest 5.

**Environment facts that change the plan**

- **No Rust toolchain is installed.** Install it with `brew install rustup`, then `rustup default stable` and `rustup target add wasm32-unknown-unknown`, and pin the version in `rust-toolchain.toml`.
- **The local LibreOffice is 26.8.1.1**, which is newer than the report's "25.x". Every finding records the exact oracle version. LibreOffice's bundled Python (`/Applications/LibreOffice.app/Contents/Resources/python`) runs the UNO scripts.
- **Page rasterising** needs `brew install poppler` (`pdftoppm`). Poppler is GPL, but it is a test-time tool only and is never linked, so that's fine. The licence ledger notes this.

## Spike 1 design

### Model (`crates/model`)

- **`Document`** holds `meta`, `styles` (named and automatic, with families paragraph, text, list, section, table, graphic and page), `body: Vec<Block>`, `parts` (the package-level preservation slots), and `doc_id`.
- **`Block`** variants:
  - `Paragraph { style, direct: PropDelta, inlines }`
  - `Heading { level, … }`
  - `List { style, items }`
  - `Table { columns: Vec<ColSpec{width}>, rows/cells }`
  - `Section { name, style, blocks }`
  - `Frame/Figure`
  - `Opaque(Slot)`
- **`Inline`** variants:
  - `Text`
  - `Span { style, direct }`
  - `Field { kind, target: Option<NodeId>, format }` (stores the target and format, never the rendered text, plus a cached display string kept only for the projection)
  - `AnnotationStart/End`
  - `ChangeMark`
  - `Bookmark`
  - `LineBreak/Tab/Space`
  - `Opaque(Slot)`
- **Tracked changes** live in a `ChangedRegion` table (insert, delete or format, with author and date), referenced by marks.
- **Every node** carries `id: NodeId` (UUID v7), `origin: Option<SourceRef>` (part plus byte span), and `dirty: bool`. Each element, style and part also has a `Slot` for unknown attributes and children.
- **Style resolution** walks parent inheritance and returns where each value came from ("Heading 2 + bold added by hand"). Principle 1 is designed into the model from day one.

### ODT I/O (`crates/odf`)

- **Dependencies, to be licence-checked before adding:** `zip` and `quick-xml` (both expected MIT), and `uuid`.
- **Reader**
  - Parses with byte offsets, so every element records its exact source span.
  - Known elements become model nodes. Unknown attributes and elements go into slots as raw byte slices.
  - The root element and namespace declarations are kept verbatim.
- **Writer**
  - Walks the model. An element that isn't dirty is written as its original byte slice.
  - A dirty element is regenerated from the model. Its untouched children are still spliced in verbatim, and its slot contents are re-emitted.
- **Package**
  - `mimetype` is written first and stored uncompressed.
  - Untouched parts are copied as raw compressed bytes.
  - Entry order and `manifest.xml` are preserved, and changed parts get manifest entries.
- **ID policy, to be measured both ways:**
  - Mode A (default for untouched content): don't inject `xml:id` into untouched elements, so their bytes stay identical.
  - Mode B (`--stamp-ids`): add `xml:id` to blocks by patching only the start tag. This measures what ID stamping costs in fidelity.

### Corpus

- **`scripts/fetch-lo-corpus.sh`**
  - Sparse, blobless clone of LibreOffice `core` at a pinned commit.
  - Copies a curated list (~150–200 `.odt` files) from `sw/qa/extras/odfexport/data`, `odfimport/data`, `sw/qa/core/data`, `sw/qa/extras/uiwriter/data` and similar.
  - Writes `manifest.toml` with path, commit and licence. The repo licence is MPL-2.0. Caveat: many of these files originate from Bugzilla attachments, so they are fetched rather than redistributed.
- **`scripts/generate_corpus.py`** (UNO, run with LibreOffice's own Python)
  - Builds one LibreOffice-authored document per core feature: styles with inheritance, direct formatting, multilevel lists, sections, tables with explicit widths, an image frame, fields (page, date, cross-ref, sequence), comments, tracked insert/delete/format, and a Danish-text sample.
  - These are real LibreOffice output, committed under CC0.
- **`corpus/municipal/README.md`** marks the place for the user's templates, which are read from a private path.

### Harness (`crates/fidelity`, CLI `skriv-fidelity run`)

For each file:

1. Round-trip it in three modes:
   - **identity**: nothing dirty;
   - **regenerate-all**: everything dirty, which tests the writer's own quality;
   - **edit-sample**: insert text into N% of paragraphs and change one style.
2. **Structural check**
   - Byte comparison per untouched element. This gives the kill metric.
   - Canonicalised XML diff of `content.xml`, `styles.xml` and `meta.xml`. Canonicalisation sorts attributes and resolves automatic-style names to their property sets, so renamed `P1`/`T3` styles aren't counted as losses.
   - Every difference is bucketed by feature.
3. **Visual check**
   - `soffice --headless --convert-to pdf` for the original and the round-tripped file. This runs in a private `-env:UserInstallation` profile, in parallel workers.
   - `pdftoppm` renders the pages, and the Rust `image` crate does a per-page pixel diff.
   - The page count must match, and the diff ratio must stay under a threshold. Failures produce a diff PNG for triage.
4. **LibreOffice → skriv → LibreOffice check**: open the round-tripped file in LibreOffice, re-save it, and compare again. This is the "zero visible loss" criterion.
5. **Report**
   - `reports/<date>/report.json` and a self-contained `index.html` showing per-feature score, per-file details, diff images and LibreOffice version.
   - The format is designed so it could be published later.

### Spike 4 pre-work (LibreOffice preservation)

`scripts/lo_preservation.py` builds small ODTs, each carrying one of:

- `xml:id` on paragraphs, headings, a table cell and a bookmark;
- `text:meta` / `text:meta-field`;
- an extra package part listed in the manifest;
- `manifest.rdf` with RDF statements;
- user-defined `meta:user-defined` metadata;
- a foreign attribute;
- a foreign element, both inline and as a block.

Each one is re-saved two ways: with `soffice --convert-to odt`, and through a UNO `loadComponentFromURL`/`storeToURL` macro. A diff reports exactly what survived, changed or was regenerated. The results go to `docs/spikes/04-libreoffice-preservation-findings.md`, with the LibreOffice version, raw diffs and a verdict on each of the report's assumptions.

### CI (`.github/workflows/ci.yml`, GitHub Actions like birk)

- **Every pull request**
  - `cargo fmt --check`, `clippy -D warnings`, `cargo test`, and `cargo deny check licenses`.
  - Biome and typecheck on the TS workspace.
  - The fidelity harness on the generated corpus.
- **Nightly, or manually**: the full LibreOffice corpus.
- **The oracle is pinned.** We install the official TDF LibreOffice 26.8 `.deb` (cached), not Ubuntu's older package, so CI and local runs use the same oracle. The version is stamped into every report.

### Tests written as we go

- **Unit tests per crate**: style inheritance, ID minting, slot capture, and the byte-span reader.
- **Property test**: identity round trip ⇒ every part is byte-identical for generated docs.
- **Golden tests** for regeneration of each feature.
